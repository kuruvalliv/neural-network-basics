Synergies with Generative AI

Evolution and big generative models patch each other's weak spots. Evolution brings search, selection and diversity; LLMs bring smart, meaningful variation. The arrows run both ways.

A1 · §13.2.1

Evolving prompts, and the prompts that evolve prompts

A prompt is a string of phrases, and we can treat those phrases like genes. EvoPrompt runs a normal GA or differential evolution, but uses the LLM itself to carry out "cross these two prompts over" and "mutate this one".

Promptbreeder goes one level up. Each individual is a pair: a task-prompt P plus a mutation-prompt M (an instruction like "simplify this instruction"). M gets evolved too. That is the self-referential part.

Jargon
task-prompt P
the instruction put in front of each question.
mutation-prompt M
an instruction telling the LLM how to change P.
hyper-mutation H
an instruction telling the LLM how to change M.
thinking style
a seed phrase such as "let's think step by step", used to build the first population.
binary tournament
pick two at random; the loser is overwritten by a mutated copy of the winner.
P′ = LLM(M + P)   ·   M′ = LLM(H + M)
M + PGlue the mutation-prompt in front of the task-prompt and send it to the LLM.
P′The LLM's answer becomes the child task-prompt.
H + MSame trick one level up: rewrite the mutation-prompt itself. Hyper-mutation rate (slider) = how often that happens.

Toy simulation. 12 phrases, each secretly helpful or harmful, plus a penalty for long prompts. Fitness is a noisy "accuracy on a Q&A batch". A mutation-prompt is a mix of three edit types (add / remove / rephrase). Three variants from Fig 13.4 run side by side with binary tournaments. A real system would call an LLM here; we sample the edits directly.

Try it: set the hyper-mutation rate to 0 and the (c) line collapses onto (b). Raise it and the edit mix itself drifts, for example toward "add" early and "rephrase" later. Results vary per seed, so run it a few times.

Book results: EvoPrompt's DE variant gained up to 25% on hard BIG-Bench tasks (3.5% on average). Promptbreeder beat the hand-designed PS+ prompting on almost every dataset, and on ETHOS hate-speech classification it went from 80% to 89%.

FOR YOUR APPS Your code-writing agent's system prompt and its "how to revise code" instruction are two separate genomes. Evolve both, and score them on a held-out batch of tasks.
What exactly makes Promptbreeder "self-referential"?

It evolves the mutation-prompts that produce new task-prompts, not only the task-prompts. The improvement method is itself being improved. EvoPrompt keeps its operator instructions fixed.

Why evaluate on a batch of questions rather than one?

One question gives a very noisy fitness. A batch estimates expected accuracy, so selection rewards prompts that generalize.

A2 · §13.2.2

Evolutionary model merging

Thousands of open models are fine-tuned copies of the same base. Merging them can produce abilities that none of them has alone. The catch: how to merge is usually guesswork. Akiba et al. let evolution search the recipe instead, in two spaces:

  • Parameter space (PS): blend weights layer by layer with evolved mixing ratios. It works like mixing paint.
  • Data flow space (DFS): choose which layers, from which model, in what order the input passes through.
θmerged(ℓ) = (1 − αℓ) · θA(ℓ) + αℓ · θB(ℓ)
θA, θBWeights of parent A (Japanese LLM) and parent B (math LLM).
ℓLayer index. Each layer (here, each layer group) gets its own ratio.
αℓHow much of B to use in layer ℓ. 0 = pure A, 1 = pure B. These numbers are the genome that evolution searches.
drag to orbit

Toy model. The surface is a made-up "Japanese-math accuracy" as a function of two layer-group ratios. Japanese skill lives mostly in A's early layers, math reasoning in B's late layers. Amber sphere = parent A, green = parent B, the line between them = plain uniform interpolation (same α everywhere). Accent dots are a live (μ,λ)-ES population.

Notice that the best point is off the diagonal. A single global blend ratio cannot reach it, but a layer-wise recipe can. That is why evolving per-layer ratios matters.

Real numbers (Table 13.1, MGSM-JA accuracy): source models scored 9.6, 18.4 and 30.0. The PS merge reached 52.0 and PS+DFS reached 55.2, beating GPT-3.5's 50.4 with a 7–10B model.

FOR YOUR APPS If you run several fine-tuned embedding or code models from the same base, a per-layer merge recipe found by CMA-ES on your eval set is a cheap way to get a "both skills" model without retraining.
PS vs DFS in one line each?

PS blends the numbers inside layers. DFS keeps layers intact and rewires which layers the data flows through, and in what order.

Why is merging a good job for evolution rather than gradients?

The recipe space is combinatorial (DFS) or non-differentiable through a benchmark score (PS). The only signal is "score on the task", which is exactly what black-box evolution needs.

A3 · §13.2.3

Fine-tuning LLMs with plain ES

Surprise result: vanilla evolution strategies can fine-tune LLMs with billions of parameters. They beat PPO and GRPO on the countdown arithmetic task (e.g. Qwen-2.5-3B: 10.0 raw → 32.5 GRPO → 60.5 ES) while using about 20% of the samples.

The key difference is where each method explores. RL explores in action space: it makes high-reward outputs more likely. ES explores in parameter space: it jitters the weights themselves and keeps whatever direction helps.

SKIP-AHEAD If the ES update below is new to you, read Ch 2 §2.2.2 first. This section assumes it.
θ ← θ + αn σ Σi=1..n Ai · εi,   εi ~ 𝒩(0, I)
θCurrent parameters (in the real study, all LLM weights).
εiA random direction. We try θ + σεi.
σPerturbation size (slider). Larger σ averages the reward over a wider patch, so it smooths out jagged bumps.
AiReward of try i, standardized (minus the mean, divided by the std).
nPopulation size (slider). More tries give a cleaner estimate of the direction.
αLearning rate (slider).
ES (circle = σ radius)gradient ascent on the same rewardbroad optimum

A real 2D ES on a reward made of one broad hill plus dense ripples, standing in for a "jagged reward landscape". The gradient follower gets stuck on the nearest ripple. Shrink σ to 0.02 and ES gets stuck too.

The book offers three explanations, still being researched: (1) a population can find one of many good weight settings (compare the lottery ticket hypothesis, §12.3.4); (2) moving weights can change the latent "behavior class" rather than memorizing outputs, and only two examples were enough to teach conciseness; (3) perturbation smooths jagged rewards. In the conciseness test, RL only got short answers by breaking the model (reward hacking). ES got them with a far smaller KL change.

Jargon
KL divergence
how far the fine-tuned model's output distribution moved from the base model's. Small is safer.
reward hacking
scoring well on the reward while failing the real intent.
FOR YOUR APPS When your reward is sparse and comes only at the end (tests pass or fail after a long generation), parameter-space ES is a serious alternative to RL for small models or LoRA adapters.
Why might ES suit long-horizon reasoning rewards?

It never needs per-token credit assignment. It scores the whole outcome for each perturbed model, so a reward that only arrives at the end is fine.

B1 · §13.3.1

ELM: the LLM as a mutation operator for code

Classic genetic programming mutates code by random token edits. Most of those break the syntax or the logic. Evolution through Large Models swaps in a diff model: an LLM trained on real commit diffs, which proposes the kind of change a programmer would make.

Key finding (Fig 13.7a): as the number of bugs to fix together grows, GP mutation's success rate collapses exponentially. The diff model holds up until the fifth bug, because it can make several coupled edits at once.

Jargon
diff
a patch: which lines change, and how.
MAP-Elites
a grid over behavior descriptors; each cell keeps its best solution (its "elite").
QD score
sum of the fitness of every filled cell. It rewards quality and diversity together.
Sodarace
2D robots built from masses and springs. ELM evolved the Python programs that build them, which makes it an indirect encoding.

x′Child program = diff applied to a randomly chosen elite.
b(x′)Its behavior descriptor: which grid cell it belongs to (here: number of terms × highest frequency used).
fFitness: how well the program fits a target curve, 1/(1+MSE).

Toy stand-in for the LLM. Programs are short expressions like 0.4·x² + 1.6·sin(2x), seeded with return 0. The "mock diff model" looks at the current error and proposes a sensible edit: add the term that best explains the error, refit all coefficients together (a coupled multi-line change), or prune a weak term. It also produces 5% broken outputs. Random mutation edits one token and breaks 25% of the time. Higher temperature makes the mock LLM pick less obvious terms, which spreads it across more cells.

ELM also fine-tuned the diff model on the diffs that worked during the run. That improved niches reached, QD score and the share of runnable diffs (Fig 13.9). The search produces the data that makes the operator better.

FOR YOUR APPS This is the blueprint for a code-evolving app: archive of programs, LLM-proposed diffs, an executable evaluator, and a log of successful diffs you can later fine-tune on.
Why does a diff model beat random mutation more as bug count grows?

Random edits must hit every fix independently, so the probabilities multiply and shrink fast. An LLM makes coupled, meaningful edits in one step.

Why pair ELM with MAP-Elites instead of plain hill climbing?

It keeps many different working programs (diverse niches) as stepping stones, rather than converging on one design.

B2 · §13.3.2–13.3.3

LMX: crossover by prompt, then the LLM as the whole ES

Language Model Crossover barely needs any code. Paste k parent genomes into a prompt, one per line. A pretrained LLM continues the pattern, and the new lines are the children. It works for anything you can write as text: bit strings, equations, sentences, image prompts, Python.

prompt = x1 \n x2 \n … \n xk  →  children = valid lines of LLM(prompt)
x1..kk randomly chosen parents (slider "parents in prompt").
LLM(prompt)Sample a continuation. Its in-context learning picks up what the parents have in common.
valid linesParse the output and throw away malformed lines. Then the usual selection step trims the population back to n.

Click bits to edit parents. Only the first k rows go into the prompt. The task is OneMax (count the 1s).

Toy stand-in. Our "LLM" continues the pattern by sampling each position from the parents' frequencies. That is a crude version of what in-context completion does with strings like these. Real LLMs pick up far richer structure, such as syntax and meaning. The book reports that LMX children are heritable (they resemble their parents) and that LMX reaches higher mean fitness than one-point crossover on OneMax, though it converges to the optimum less often (16/20 vs 20/20).





EvoLLM: ask the LLM for the next ES mean §13.3.3


Next step up: let the LLM be the strategy. Every past evaluation goes into a context buffer. Solutions are written as integers, since tokenizers handle floats badly. The buffer is sorted from worst to best, a desired fitness fquery is appended, and the LLM continues with a new mean. You then sample around that mean.


H = {Xg, Fg}g=1..G → top-K gens × top-M each → prompt + fquery → xLLM → x ~ 𝒩(xLLM, σ²)


HHistory of solutions Xg and fitnesses Fg for each generation g.
top-MHow many records go into the prompt (slider). More context means more pattern to continue.
fquery"Give me something scoring this well". The same trick as a decision transformer.
xLLMThe LLM's proposed mean. If it fails to improve, fall back to sampling around the best so far.




prompt sent this generation










Toy stand-in. The mock LLM reads the sorted integer records and "continues the trend": it extrapolates from the best record away from the centroid of the others. Points: muted = buffer, accent = this generation, ring = proposed mean.




Book findings: EvoLLM beat random search and Gaussian hill climbing on BBOB functions, and often beat diagonal-covariance ES, usually within 10 generations. Oddly, smaller LLMs did better than larger ones. To scale, it splits dimensions into blocks and queries each block separately.


FOR YOUR APPS LMX is the 10-line operator to try first on any text genome (configs, prompts, SQL, small functions). EvoLLM's lesson is about format: write numbers as integers and sort records worst to best, and the model reads the pattern far better.


What LLM ability makes LMX domain-general?
In-context (few-shot) pattern completion: given a few examples, it produces new examples that share their structure.


Why does EvoLLM discretize to integers?
Tokenizers split floats into awkward pieces, which makes the numeric pattern hard for the model to follow.








B3 · §13.3.4


AlphaEvolve: the full code-evolution loop


AlphaEvolve is ELM grown into a distributed production system. You give it a program with EVOLVE-marked blocks plus an evaluate() function. Then four parts run asynchronously:


    

  • Program database: a MAP-Elites and island-model hybrid archive. It keeps good and diverse programs.
    • 

  • Prompt sampler: builds a rich prompt from a parent, some "inspiration" programs, past scores and instructions.
    • 

  • LLM ensemble: Gemini Flash for many fast ideas, Pro for fewer deep ones. Each returns a diff, or a whole block for big changes.
    • 

  • Evaluators pool: runs the child program and returns one or more scores.


parent, insp ← DB.sample() → prompt ← build(parent, insp) → diff ← LLM(prompt) → child ← apply(parent, diff) → DB.add(child, eval(child))

Results across four areas:


    

  • Mathematics: 4×4 complex matrix multiply in 48 multiplications (Strassen-based record: 49). Over 50 open problems: matched the best known in 75%, improved in 20% (e.g. 593 spheres for the 11-D kissing number).
    • 

  • Infrastructure: a data-center scheduling heuristic that recovers 0.7% of Google's fleet compute, and a 23% faster matmul kernel that cut Gemini training time by 1%.


SKIP-AHEAD Read ELM before this if you jumped here. AlphaEvolve is the same idea (LLM diffs + QD archive) with engineering added. Island models are covered in the book's GA chapters.


FOR YOUR APPS To copy the architecture: mark the regions that may change, write a fast deterministic evaluator first, use a cheap model for volume and a strong model for depth, and keep islands so one lineage can't take over.


Why sample "inspirations" in addition to the parent?
They show the LLM other successful ideas to recombine, which works like crossover, and they keep the prompt varied. That supports diversity.


What happens with very high selection pressure in the toy?
Nearly every child comes from the top program. Early progress is fast, but the database loses variety and can stall. Low pressure explores more but improves more slowly.

Generative content: levels, latents and dreams


Here the generative model is not an LLM operator. It is a learned genotype → phenotype map. Evolution searches its small input space while the model guarantees that outputs look realistic.

World models: V, M, C


Give the agent a generative model of its own world. V (a VAE) squeezes each frame into a small code z. M (an RNN) predicts the next z and holds memory h. C is a tiny controller acting on [z, h]. V and M train with gradients. C is small, so CMA-ES evolves it.


zt = V(ot)  ·  at = Wc[zt, ht] + bc  ·  ht+1 = M(ht, zt, at)


otRaw observation (pixels).
zt16-D compressed "what I see now". In effect, an embedding.
htRNN hidden state: "what I expect next".
Wc, bcThe only evolved parameters. Linear C on z alone needs just 17×3 = 51 numbers.

Real data from the book. CarRacing scores (§13.5.2) and DoomTakeCover survival time (task is solved at >750). At low τ the dream is too predictable, so C finds exploits that do not exist in reality. Raising τ makes the dream harder and the policy transfers.




FOR YOUR APPS This is embedding-based decision making in its cleanest form. Freeze a strong encoder (V, your embedding model), optionally add a predictor (M), and evolve a tiny decision head (C). When you train against a learned simulator, add noise (τ) so the policy can't exploit its flaws.


Why keep C tiny?
All the heavy representation learning is done by gradient descent in V and M. A small C keeps the evolutionary search space small (hundreds of parameters), where CMA-ES is very effective and credit assignment is easy.


MarioGAN vs MarioGPT: what's the core trade-off?
LVE gives precise control through any fitness function but needs a search per request. MarioGPT answers a text request immediately but can't guarantee constraints, so it uses novelty search for diversity.








Recap


    

  • A · Evolution → LLMs
    • Input: evolve prompts (EvoPrompt), and evolve the mutation-prompts too (Promptbreeder).
    • Combination: evolve per-layer merge ratios (PS) and layer routing (DFS).
    • Weights: vanilla ES fine-tunes billion-parameter LLMs. It explores parameter space, is sample-efficient, and resists reward hacking.
    • 

  • B · LLMs → evolution
    • Operators: ELM diff mutation (with MAP-Elites, plus fine-tuning the diff model) and LMX crossover by prompt.
    • Strategy: EvoLLM proposes ES means from a sorted integer history.
    • System: AlphaEvolve combines a program DB, prompt sampler, LLM ensemble and evaluators, with real math and infrastructure wins.
    • 

  • C · Generative content
    • LVE (MarioGAN): evolve the latent vector of a frozen generator. MarioGPT: text-conditioned levels plus novelty search.
    • World models: V and M learned by gradients, C evolved. Train in the dream with temperature for transfer.

Review questions (paraphrased from §13.6)


1. How does Promptbreeder's self-reference differ from EvoPrompt?
Promptbreeder also evolves the mutation-prompts (via hyper-mutation). EvoPrompt only evolves task-prompts with fixed GA/DE operator instructions.


2. What drove EvoPrompt's gains on BIG-Bench Hard?
An LLM performing GA/DE crossover and mutation on prompts, with selection on a dev set. DE reached up to +25% (+3.5% average).


3. Parameter space vs data flow space merging, and why can merges show new abilities?
PS blends weights per layer. DFS picks and orders layers across models. Evolution finds unintuitive recipes that combine skills, such as Japanese plus math.


4. What do diff-based LLM mutations offer GP?
Syntactically valid, semantically meaningful, coupled edits learned from real code changes. Success degrades far more slowly as the needed fixes grow.


5. Which LLM capability makes LMX general?
In-context few-shot pattern completion over any textual representation.


6. How does EvoLLM change the role of the LLM in ES?
The LLM becomes the update rule. It reads a sorted history and proposes the next search mean, instead of only generating variants.


7. MarioGAN vs MarioGPT trade-offs?
Search-based precise control vs instant text control. Diversity comes from the optimizer vs from novelty search.


8. Roles of V, M, C, and the effect of temperature when training in the dream?
V compresses, M predicts and remembers, C acts. Higher τ makes the dream stochastic and harder to exploit, which improves transfer to reality.

How a Function's Inputs and Outputs Relate関数の入力と出力の関係

What structure connects $x$ and $y$, and how can we exploit it?$x$ と $y$ をつなぐ構造は何か、どう活かせるか？

Shift a photo of a cat two pixels to the left. Every pixel value changes, but it is still a cat. A model that has to learn this separately for every possible shift needs far more data than one that knows it from the start. What other facts like this are hiding in our data?

猫の写真を2ピクセル左にずらすと、ピクセルの値はすべて変わりますが、猫のままです。ずらし方ごとにこれを学ばなければならないモデルは、最初からそれを知っているモデルよりはるかに多くのデータを必要とします。私たちのデータには、他にどんな事実が隠れているでしょうか。

  • Use conditional independence to cut down how much must be learned.
  • Recognize when high-dimensional inputs really live on a low-dimensional manifold.
  • Tell invariance from equivariance.
  • See composition and smoothness as assumptions about the target function.
  • 条件付き独立を使って、学ぶべき量を減らす。
  • 高次元の入力が、実は低次元の多様体の上にある場合に気づく。
  • 不変性と同変性を区別する。
  • 合成と滑らかさを、目標とする関数についての仮定として見る。

5.1 Dependence and conditional independence5.1 依存と条件付き独立

Add temperature $T$ to the rain example. Warm air holds more water, so temperature affects humidity $H$, and humidity affects rain $R$. Does temperature affect rain directly, or only through humidity? The answer changes how many numbers we must learn.

雨の例に気温 $T$ を加えます。暖かい空気はより多くの水分を含めるので、気温は湿度 $H$ に影響し、湿度は雨 $R$ に影響します。では、気温は雨に直接影響するのでしょうか、それとも湿度を通してだけでしょうか。その答えによって、学ぶべき数の個数が変わります。

A full table over (T, H, R) has 3 × 3 × 2 = 18 cells, so 17 free numbers. If you delete the arrow T → R, how many remain?(T, H, R) の表をまるごと持つと 3 × 3 × 2 = 18 マス、自由な数は17個です。矢印 T → R を消すと、何個残るでしょうか？

11. The rain table now needs one number per humidity level (3) instead of one per (temperature, humidity) pair (9).

11個です。雨の表は、（気温, 湿度）の組ごとに1つ（9個）ではなく、湿度の段階ごとに1つ（3個）で済むようになります。

$R$ is conditionally independent of $T$ given $H$, written $R\perp T\mid H$, if $p(r\mid h,t)=p(r\mid h)$. Then the joint distribution factorizes:

$p(r\mid h,t)=p(r\mid h)$ が成り立つとき、$H$ のもとで $R$ は $T$ と条件付き独立であるといい、$R\perp T\mid H$ と書きます。このとき同時分布は因数分解できます：

$$p(t,h,r)=p(t)\,p(h\mid t)\,p(r\mid h).$$

5.2 Dimension, redundancy, and manifolds5.2 次元・冗長性・多様体

A 100×100 photo is a point in a 10,000-dimensional space. Almost every point in that space is static noise, though, and real photos occupy a thin, curved sliver of it. The same is true in miniature below: two coordinates, but only one really matters.

100×100 の写真は、10,000次元の空間の1点です。しかし、その空間のほとんどの点はただの砂嵐で、本物の写真が占めるのは、細く曲がったごく一部だけです。下の図はその小型版です。座標は2つありますが、本当に重要なのは1つだけです。

The manifold hypothesis: real high-dimensional data concentrate near a low-dimensional surface (a manifold), and the target $p(y\mid x)$ varies mainly along it. Straight-line distance in the input space can then be misleading.

多様体仮説：現実の高次元データは低次元の面（多様体）の近くに集まっており、目標の $p(y\mid x)$ は主にその面に沿って変化する、という仮説です。このとき、入力空間での直線距離は当てにならないことがあります。

5.3 Invariance and equivariance5.3 不変性と同変性

Some questions about an input don't care where it is or which way it faces (“is it a triangle?”). Others care in a predictable way (“where is its centre?”). These two kinds of symmetry are the most valuable structure a model can be given.

入力についての問いの中には、それがどこにあるか、どちらを向いているかを気にしないものがあります（「三角形か？」）。一方、予測できる形で気にするものもあります（「重心はどこか？」）。この2種類の対称性は、モデルに与えられる構造の中で最も価値のあるものです。

For a transformation $g$ (shift, rotation, …): $f$ is invariant if $f(g\cdot x)=f(x)$, and equivariant if $f(g\cdot x)=g\cdot f(x)$.

変換 $g$（平行移動、回転など）について、$f(g\cdot x)=f(x)$ なら $f$ は不変、$f(g\cdot x)=g\cdot f(x)$ なら同変です。

5.4 Composition5.4 合成

Many complicated relationships are built from simple steps: edges make shapes, shapes make objects, objects make scenes. If the target has that structure, the model should have it too.

複雑な関係の多くは、単純なステップの積み重ねでできています。エッジが形を作り、形が物体を作り、物体が場面を作ります。目標の関数がそのような構造を持つなら、モデルも同じ構造を持つべきです。

Starting from the W shape, which adds new corners: fold, or −1 and then fold?W の形から始めて、新しい角を作るのはどちらでしょうか。「折る」だけか、「−1 してから折る」か？

“−1 then fold”: the 3 corners become 5. Folding alone does nothing, because the W is never negative. Shifting first pushes part of the curve below zero, and the fold bends it back up, creating new corners.

「−1 してから折る」です。3つの角が5つになります。W は負にならないので、折るだけでは何も起きません。先にずらすと曲線の一部が0より下に来て、折るとそこが上に曲がり、新しい角ができます。

5.5 Smoothness and locality5.5 滑らかさと局所性

Between two data points we have no data at all. The only reason we can predict there is an assumption: nearby inputs have similar outputs. How “nearby” is defined is itself a choice, and a consequential one.

2つのデータ点の間には、データがまったくありません。それでもそこで予測できる唯一の理由は、「近い入力は似た出力を持つ」という仮定です。何を「近い」とするかもまた選択であり、その影響は大きいのです。

“A flexible enough model doesn't need assumptions.” Every model that predicts between data points is making assumptions. The only question is whether they match the world. Flexibility in directions the data does not need just wastes data.

「十分に柔軟なモデルなら仮定はいらない」というのは誤りです。データ点の間を予測するモデルは、どれも何かを仮定しています。問題は、その仮定が世界と合っているかどうかだけです。データが必要としない方向の柔軟さは、データを無駄にするだけです。

Structure in the data (independence, low dimension, symmetry, composition, smoothness) tells us what kind of function to look for. That is inductive bias.

データの構造（独立性、低次元性、対称性、合成、滑らかさ）は、探すべき関数の種類を教えてくれる。それが帰納バイアスである。

An image classifier should output “cat” wherever the cat is. Should it be invariant or equivariant to shifts? What about a model that outputs a box around the cat?画像分類器は、猫がどこにいても「猫」と出力すべきです。平行移動に対して不変であるべきでしょうか、同変であるべきでしょうか。猫を囲む枠を出力するモデルはどうでしょうか？

The classifier should be invariant: the label doesn't move. The box model should be equivariant: shift the cat and the box should shift by the same amount.

分類器は不変であるべきです。ラベルは動かないからです。枠を出すモデルは同変であるべきです。猫をずらしたら、枠も同じだけずれるべきだからです。

探すべき構造は分かりました。ほぼ何にでも当てはまるほど豊かでありながら、これらの仮定に沿った形をした関数族は、どう組み立てればよいでしょうか。→ 第6章
